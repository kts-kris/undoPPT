## 1. 文档基本信息 (Document Metadata)

* **产品名称**：undoPPT (演示文稿智能解构与重构超级智能体)
* **版本号**：v3.7.0
* **编写日期**：2026-10-06
* **状态**：正式发布 / 生产实施
* **核心目标**：
  1. 让蓝图里的**每个数字都能说出出处**，没有出处的数字在成品上明确标为"待核"；
  2. 提供从文档到蓝图的**可追溯数据通道**：`ingest` 抽取、`cite` 回填；
  3. 提供**交付闸门**：`build --final` 在仍有待核数字时拒绝构建；
  4. 让 demo **遵守产品自己的规则**，作为样板而不是反例；
  5. 100% 向后兼容：`source` / `status` 均为可选字段，不改变既有蓝图。

## 2. 背景与问题剖析 (Background)

血肉（内容）是 PPT 的实质。v3.6 解决了"信息不足就生成"和"内容撑不起版式"，但没有解决更危险的一类问题：**数字看起来像证据，却无法核验**。

v3.7 立项前的实测：

| # | 现象 | 根因 |
|---|---|---|
| 1 | 规划器输出的"35% 成本节降""94.8% 完成率"等数字都是模板编造，但页面上与真实数据毫无区别 | 蓝图没有出处字段，渲染器、审计器都不关心数字从哪来 |
| 2 | 用户给了文档，数字仍靠 Agent 手工抄写，抄错无从发现 | 没有从文档到蓝图的可追溯通道 |
| 3 | demo 自己触发 8 条审计项（4 条套话、3 条缺量化、1 条主旨偏离），并以四条要点结尾，没有决策闭环 | demo 写于规则出现之前，从未被自己的审计检验 |
| 4 | 套话告警只说"不要用'闭环'"，不说改成什么 | 规则是事后报警，不是起草时可用的指引 |

## 3. 需求 (Requirements)

### 3.1 数据出处模型 (`core/provenance.py`)
- **R1 字段**：`source`（字符串或列表）与 `status`（`verified` / `estimate` / `illustrative` / `todo`），可写在页面或嵌套条目上。页面级覆盖整页；条目级只覆盖该条目并优先。
- **R2 数字的定义**：百分比、倍数、金额、时长、计量单位的数字、"5 个人头"这类编制数。年份、季度（Q3）、优先级（P0）、层级（L4）、结构性计数（"3 个支柱"）不是数字。
- **R3 待核**：没有任何 `source` 覆盖的数字，以及 `status: todo` 的数字，都是待核。`illustrative` 不算待核但必须标注。
- **R4** 原生图表数据视为一组数字，需要 `source`。

### 3.2 成品上的标记
- **R5** PPTX 与 HTML：页脚显示 `来源：…`（`status` 为 `estimate` / `illustrative` 时加"估算 · / 示例数据 ·"前缀）；存在待核数字的页面右上角显示琥珀色 `待核 N 项` 徽标。
- **R6** 演讲备注与 HTML 认知抽屉（`N` 键）列出出处、估算、示例数据与待核数字。
- **R7** 页脚与徽标在版面适配之后添加，**不得改变内容块的位置**。

### 3.3 数据通道
- **R8 `cli.py ingest`**：从 `.md` / `.txt` 抽取数字，出处为 `文件:L行号`；从 `.csv` 抽取，出处为 `文件:第N行·列名`，并利用表头括号里的单位（`数值(万元)` + `1200` → `1200万元`）。Excel 明确拒绝并提示导出 CSV。
- **R9 `cli.py cite`**：按数值把出处回填到蓝图。**保守原则**：页面级 `source` 覆盖整页所有数字，因此只有当该页**全部**没有出处的数字都匹配到时才写入；部分匹配只写 `source_candidates`，数字仍保持待核。`cite` 不写 `status`（匹配只证明数字出现在文档里，不证明用在同一个论断上）。
- **R10 `build --final`**：仍有待核数字时退出码 1 并拒绝构建；通过时隐藏待核徽标。普通 `build` 保留徽标，用于草稿。

### 3.4 审计
- **R11** `UNSOURCED_FIGURES_P<n>`、`EVIDENCE_TODO_P<n>`（各扣 2 分，合计最多 10 分）；`EVIDENCE_ESTIMATE_P<n>`、`EVIDENCE_ILLUSTRATIVE_P<n>` 仅提示。审计结果含数字统计，`audit` 命令输出一行汇总。
- **R12 套话替换建议**：9 个套话词各带具体改写方式（`suggestion` 字段，并写入消息）。

### 3.5 demo
- **R13** demo 以决策闭环页收尾：三个方案（恰好一个推荐）、推荐理由、待批清单。
- **R14** demo 不含禁用词，核心实证均量化；编造的数字统一标 `illustrative`。目标：审计无警告。

### 3.6 渲染修正
- **R15** 字号地板只抬高小于 12pt 的文字，不动标题；短标签（≤16 字）不得因放大而折行（v3.5 的整框等比放大会产生孤字）。
- **R16** 决策页待批清单框底边为 7.0 英寸，避开页脚。

## 4. 验收标准 (Acceptance Criteria)

| 标准 | 结果 |
|---|---|
| 全部测试通过 | 105 项（原 68 + 新增 37） |
| demo 审计 | 100/100，无警告（v3.6：8 条）；仅有 `illustrative` 提示 |
| demo 数字 | 64 个，全部标注为示例数据，待核 0 |
| demo 结尾 | 3 个方案、1 个推荐、推荐理由、3 条待批事项 |
| PowerPoint 真实渲染：demo | 8 页，静态 lint 0 条；页脚可见、决策页清单框不碰页脚、层级名单行 |
| 12 个企业场景生成的 PPTX | 静态 lint 0 条；PowerPoint 空白带 0 页超限 |
| `cite` 部分匹配 | 不写 `source`，只写 `source_candidates`，未匹配数字仍待核 |
| `build --final` | 有待核数字时退出码 1 且不产出文件；全部有出处时退出码 0 且无徽标 |
| 页脚/徽标不改变内容位置 | 有/无页脚的两份 PPTX，内容形状的纵坐标完全一致 |
| 端到端 | `ingest` → `cite` → `build --final` 对一份样例文档通过 |

## 5. 范围外与已知限制 (Out of Scope & Known Limits)

- 数字识别基于模式：会漏掉"三成"这类文字写法的数字，也可能把带单位但并非论断的数字算进去。
- `cite` 的匹配只比较数值字符串，不理解语义；`verified` 必须由人判定。
- 不直接读取 Excel；请先导出 CSV。
- 规划器仍会编造数字（它是兜底作者）；v3.7 让这些数字**显形为待核**，而不是阻止它们被写出。
