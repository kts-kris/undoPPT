## 2. 背景与问题剖析 (Background)

产品的四层结构里，骨架（主题与提纲）决定上限。v3.5 之前，骨架的质量完全取决于规则引擎与 Agent 的临场发挥，且**没有任何机制阻止在信息不足时生成**。

v3.6 立项前的实测：

| # | 现象 | 根因 |
|---|---|---|
| 1 | 输入"帮我做一份关于 AI 的汇报"，规划器产出 6 页，审计 **91.7 分、评级 A**；核心主旨是"从局部要素粗放投入全面迈向以实质成果为导向的关于 AI 的汇报系统性重塑与闭环" | 审计只看蓝图结构，对"垃圾进"完全无感；规划器靠模板与套话填充 |
| 2 | 规划器输出的页面常常只有三行短标题，撑不起选定的版式 | 没有"正文是否足够"的检查 |
| 3 | 蓝图里写了 `columns[].points`，成品里一个要点也没有 | 规格书与规划器使用 `points`/`tag`，渲染器读 `bullets`/`badge` |
| 4 | 蓝图 `cross_mapping` 页 90% 的文字没有出现在 PPTX 里；`horizons_curve` 74%，`content_columns` 60%，`maturity_ladder` 50%，`matrix_2x2` 44% | 同上：五种图元的字段名在规格书与渲染器之间不一致，且回退是静默的 |
| 5 | "内部技术分享"类需求被判为通用汇报 | 场景分类关键词缺失 |

第 3、4 项是**内容正确性**问题，比版面问题更严重：用户看不到的东西，也就无从发现它丢了。

## 3. 需求 (Requirements)

### 3.1 认知契约探针 `cli.py probe`
- **R1** 在写任何一页之前，对用户请求（及可选参考文档）判断：场景；Q1 主旨、Q2 受众与立场、Q3 认知差、Q4 终局行动是否已知；该场景 3~4 个专属事实是否已知。
- **R2** Q2（谁在听）与 Q4（要他做什么）是**阻塞项**：二者缺一，`ready` 必为 false。
- **R3** `ready` = 已知槽位占比 ≥ 70% 且无阻塞项缺失。
- **R4** 返回按优先级排序的追问清单：阻塞项在前，通用契约次之，场景事实最后。
- **R5** 12 个企业场景均有专属事实检查（立项问预算与备选，QBR 问偏差与归因，RFC 问回滚，故障复盘问时间线，晋升问净增量等）。
- **R6** `plan` / `generate` 在完备度低时打印同样的提示，但**不中止**（向后兼容）。
- **R7** 探针是启发式的：只判断是否**提及**，不判断是否**正确**。文档与输出中明确标注。

### 3.2 提纲样例 `docs/zh/scenario_outlines.md`
- **R8** 12 个场景各一份：听众闸门、必须拍板的事、六页提纲（图元、结论式标题示例、本页使命、**必备血肉**）、红线。
- **R9** 页序与图元与规划器的实际输出一致；以测试保证文档不漂移。
- **R10** 文档明确总规矩：**页数服从证据，不是证据服从页数**。

### 3.3 血肉预算审计
- **R11** `THIN_CONTENT_P<n>`：页面正文（不含页眉标题）短于该图元的最小值。各图元最小值取规划器自身输出下限的约一半，只拦明显偏薄的页面。
- **R12** `EVIDENCE_BUDGET_P<n>`：指标页中带数值的指标不足一半。
- **R13** 封面与原生图表豁免；两项合计最多扣 12 分。

### 3.4 蓝图兼容层 `core/blueprint_compat.py`
- **R14** 把规格书/规划器的字段映射到渲染器字段：`columns[].points→bullets`、`tag→badge`；`cross_mapping` 的 `layer/current/target/action`；`horizons` 的 `horizon/name/kpi`；`levels` 的 `step/focus/target`；`quadrants` 的 `desc/tag` 与 `axes`。
- **R15** 只在渲染器字段缺失时填充，不覆盖已有字段；不修改入参；PPTX 与 HTML 共用。
- **R16** 回归测试：12 个场景生成的蓝图，在受影响的图元上，每个字符串都必须出现在 PPTX 与 HTML 中。

### 3.5 其他
- **R17** `SKILL.md` 阶段 1 改写为"信息不足，不生成"，含探针流程与"先问"循环；`plan`/`generate` 定位为兜底。
- **R18** 修复"技术分享/内部分享/经验分享"的场景分类；蓝图版本取 `core.__version__`。
- **R19** 架构栈层级说明在 4 层时不再被隐藏。

## 4. 验收标准 (Acceptance Criteria)

| 标准 | 结果 |
|---|---|
| 全部测试通过 | 68 项（原 44 + 新增 24） |
| 模糊请求（"做个 PPT"、"帮我做一份关于 AI 的汇报"） | `ready: false`，阻塞项为 Q2、Q4，完备度 ≤ 25% |
| 信息充分的请求 | `ready: true` |
| 12 个场景的提示均被正确分类 | 是（含此前误判的"内部技术分享"） |
| 受影响图元的文字保真（12 个场景 × PPTX/HTML） | 0 丢失（v3.5：cross_mapping 90%、horizons 74%、columns 60%、ladder 50%、matrix 44%） |
| 变异验证：关闭兼容层 | 两个保真测试均失败 |
| 规划器自身输出 | 不触发 `THIN_CONTENT`、`EVIDENCE_BUDGET`；12 套均过 v3.5 的静态 lint 与 PowerPoint 空白带检查 |
| 提纲文档与规划器 | 12 个场景的图元序列逐一一致 |

## 5. 范围外与已知限制 (Out of Scope & Known Limits)

- 探针只判断是否**提及**，不判断是否**正确**；它不能替代向用户提问。
- 规划器仍是规则引擎，没有真实洞察。本版把它降级为兜底，不重写。
- 决策收尾页在有 `options` 时不绘制 `points`（设计如此，选项、推荐与待批清单占满页面）。
- 数据来源追溯、"待核"标记、`ingest` 留待 v3.7。
