## 2. 背景与问题定义 (Problem Statement & Background)

### 2.1 行业现状与 AI 生成 PPT 的两大痼疾
当前以大模型驱动的演示文稿生成在内容表现和受众体验上普遍存在两个极端缺陷：

```
┌────────────────────────────────────────────────────────┐     ┌────────────────────────────────────────────────────────┐
│             痼疾一：内容浮夸与“AI 假大空黑话”            │     │              痼疾二：动效缺失或动效过载                 │
├────────────────────────────────────────────────────────┤     ├────────────────────────────────────────────────────────┤
│ • 习惯性使用“不仅是X，更是Y”、“X是Y”、“闭环”、“抓手”等套话│     │ • 传统工具要么完全是死板静态切片，现场讲解缺乏视觉引导；│
│ • 技术方案空谈“高可用”，无指标分布、无故障边界、无回滚路径│     │ • 要么模仿某些网页动效搞眼花缭乱的旋转缩放，喧宾夺主；│
│ • 商业路演通篇宏大叙事，无单客经济模型，伪造测试数据；│     │ • 无法在 PPTX 保持 Office 原生兼容的同时提供步进式展开│
└────────────────────────────────────────────────────────┘     └────────────────────────────────────────────────────────┘
```

### 2.2 借鉴 open-kimi-ppt-skill 的核心启示
通过逆向学习 `open-kimi-ppt-skill`，我们发现其两项极其突出的优势：
1. **场景指南具备严格的“避坑红线”（General Prohibitions）**：其对技术工程、管理报告、学术研究等细分场景制定了极为严苛的“反套话”规则（如禁止使用常见 AI 句式、架构图必须标注调用方向与异常路径、禁止使用无意义的卡片墙等）；
2. **动效维度的系统化探索**：不仅在 PPTX 导出时默认注入丝滑的淡入淡出（Fade）切页过渡，还在 DSL 中探索了页内元素的入场时序动效。

### 2.3 undoPPT 的进阶定位
`undoPPT` 在借鉴上述两点的同时，严格坚持 **“绝不让 Agent 盲猜像素坐标”** 与 **“100% 纯本地离线闭环生成”** 的底层底座优势：
* 场景指南的红线规则不仅作为 Prompt 约束，更进一步**沉淀为 `cli.py audit` 的确定性代码规则拦截器（Blacklist & Rules Engine）**；
* 动效维度不搞破坏 Office 兼容性的脆弱复杂动效，而是构建 **“切页过渡 + 15 大图元认知展开时序（Primitive Staged Disclosure）”**，在 PPTX 保持 100% 原生兼容的同时，在单文件 HTML 交付端提供无与伦比的现场步进演讲体验。

## 4. 详细功能规约 (Detailed Requirements Specification)

### 4.1 场景避坑红线体系 (Scenario Anti-Pattern Red Lines)

#### 4.1.1 通用禁忌红线（General Red Lines）
所有场景生成的演示文稿必须遵循以下红线，违反者在 `cli.py audit` 中直接予以告警并扣分：

1. **语言风格红线（禁止 AI 腔调与空洞词汇）**：
   - 严禁句式：*“不仅是……，更是……”*、*“……是……的基石/必由之路”*、*“为什么/凭什么/怎么做”*、*“N 大战场 / N 维路径”*。
   - 严禁空洞管理黑话：*“打法”*、*“闭环”*、*“抓手”*、*“赋能”*、*“底层逻辑”*、*“颗粒度”*、*“对齐”*（无具体执行动作时）、*“盘活”*、*“解构”*、*“破局”* 等无实际信息增量的套话堆砌。
2. **标题先行红线（Action Titles）**：
   - 严禁纯中性被动命名：禁止使用 *“现状分析”*、*“背景介绍”*、*“系统架构”*、*“思考与探索”*、*“总结与回顾”* 等无观点的标题。
   - 必须采用**动宾短语或结论先行句**，如：*“痛点：单体架构在 5 万 QPS 峰值下发生雪崩”*、*“方案：通过三层解耦与分库分表将延迟压降至 8ms”*。
3. **真实性与实证铁律（Truth-in-Evidence）**：
   - 严禁伪造测试基准（Benchmarks）、虚构指标与捏造案例。
   - 真实数据缺失时，必须标注 `[待实测]`、`[业务假设]` 或 `[行业参考]`，严禁用杜撰的精密小数伪装实证。
   - 严禁仅使用主观形容词（如 *“极高性能”*、*“超强稳定性”*），必须附带基准度量（如 *“P99 < 15ms”*、*“SLA 99.99%”*）。
4. **视觉与结构降噪红线**：
   - 严禁为了填补空间而堆砌无意义的卡片墙（Card Walls）；
   - 严禁全篇清一色采用三等分或四等分的呆板排版；
   - 严禁滥用蓝紫霓虹、高光渐变等干扰阅读的信息垃圾。

### 4.2 动效维度体系架构 (Motion Architecture Specification)

#### 4.2.1 动效指导原则：认知克制与步进聚焦 (Cognitive Restraint)
* **服务于受众认知节奏**：动效的唯一价值是帮助演讲者控制观众的视线焦点，引导认知按照 `论点先行 ➔ 事实展开 ➔ 数据实证 ➔ 总结决策` 的逻辑节奏递进。
* **杜绝杂耍式动效**：严禁出现旋转、翻滚、剧烈弹跳或无规则游走的动画，统一采用 **淡入（Fade）、平滑推移（Push）、微位移渐显（Stagger Reveal）**。

#### 4.2.2 Level 1: 幻灯片切页过渡 (Slide Transition)
* **规范字段**：
  * 在 Blueprint 根节点定义全局 `transition_effect`（默认 `"fade"`）；
  * 允许在具体页中覆写 `transition_effect`。
* **支持效果**：
  * `"fade"` (默认推荐)：高雅克制，平滑淡入淡出，时长 0.4s；
  * `"push"`：向左推移，适用于时间轴推进、演进阶梯或里程碑展示；
  * `"wipe"`：向右擦除，适用于前后方案鲜明对比；
  * `"none"`：瞬时切换，适用于极简打印或快速翻阅场景。
* **PPTX 物理实现**：
  * 利用 `python-pptx` 的底层 `oxml` 机制，在 slide XML 树中注入标准 OOXML 节点：
    ```xml
    <p:transition xmlns:p="http://schemas.openxmlformats.org/presentationml/2006/main" spd="fast" advClick="1">
        <p:fade/>
    </p:transition>
    ```
  * 严格遵循 PPTX CT_Slide 模式规范，插入位置位于 `<p:cSld>`（及可选 `<p:clrMapOvr>`）之后、`<p:timing>` 之前，保证 100% 通过 PowerPoint、WPS 与 Keynote 的 XML 校验。
* **HTML 单文件实现**：
  * 在切换幻灯片时，通过 Tailwind CSS 动画容器添加 `opacity-0` 到 `opacity-100` 的硬件加速渐变过渡。

#### 4.2.3 Level 2: 15 大图元认知展开时序 (Primitive Staged Reveal)
为 15 大核心图元设计天然匹配人类心智节奏的时序显现策略：

| 图元标识 | 动效节奏 (Motion Rhythm) | 展开时序语义 |
| :--- | :--- | :--- |
| `bento_cards` | `stagger` | 卡片从左至右或按权重错落淡入，高亮重点卡最后登场形成视觉焦点 |
| `architecture_stack` | `bottom_up` | 底层基础设施 ➔ 中间调度底座 ➔ 顶层业务应用 逐层堆叠成型 |
| `timeline` / `process_flow` | `sequential` | 时间/流程节点沿主轴线依次点亮，传达因果推进感 |
| `matrix_2x2` | `quadrant_reveal` | 坐标轴确立 ➔ 象限卡片按战略优先级依次呈现 |
| `maturity_ladder` | `step_climb` | 从起步期 L1 阶梯向上攀升至成熟期，直观展示进阶势能 |
| `horizons_curve` | `horizon_unfold` | H1 守成主业 ➔ H2 突破增长 ➔ H3 颠覆远期 依次展开 |
| `metric_spotlight` | `count_spotlight` | 核心大字数值优先突出，对比浮动标签随后锁定 |
| `standard_table` | `row_by_row` | 表头确立后，核心对比行依次呈现 |

* **HTML 单文件落地（步进演讲模式）**：
  * 在单文件 HTML 中，支持通过按 `Space`（空格）或 `→`（右方向键）进行**“子步进展开（Sub-step Reveal）”**：
  * 初次进入幻灯片时，仅展示大标题、副标题与底板框架；
  * 连续轻按空格键，图元内部的卡片、架构层级或时间轴节点依次高亮显现；
  * 当所有组件全部展开后，下一次按空格才翻入下一页；
  * 按 `N` 键可随时滑出认知动力学抽屉，两者完全无缝协同。
* **PPTX 兼容性与降级保障**：
  * PPTX 默认以开箱即用、完整呈现场景为主（确保导出即可直接打印、分发与二次修改），在保证矢量与格式无损的前提下，注入 slide-level transition；
  * 高阶进阶模式提供 `--motion staged` 选项，可将带复杂时序图元的页面自动编排为递进切片（Slide Staging），确保在无需任何复杂插件的情况下，在任何投影设备上直接单键步进放映。

## 6. 质量审计与验收标准 (Acceptance Criteria)

### 6.1 自动化审计拦截验收 (`cli.py audit`)
1. **黑话拦截率**：输入包含黑话词库（“不仅是X更是Y”、“抓手闭环”）的蓝图，审计器必须 100% 告警标红，在 `structural_score` 或 `semantic_score` 中实施扣分，并明确指出整改建议；
2. **场景专有规则检测**：技术架构蓝图若通篇无任何量化度量或 SLA 指标，审计器扣除“实证密度分”并警告；
3. **真实性标记宽容度**：蓝图如果包含明确的假设标记（如 `[待实测]`、`[设计预估]`），不视为伪实证，给予诚信加分。

### 6.2 动效呈现双端验收
1. **PPTX 播放体验**：导出的 `presentation.pptx` 在 Microsoft PowerPoint、Apple Keynote 与 WPS Office 中全屏播放时，幻灯片之间应流畅呈现淡入淡出（或指定的推移）过渡，XML 结构无报错或破损警告；
2. **HTML 步进演播体验**：导出的 `presentation.html` 在 Chrome/Safari/Edge/Firefox 中打开时，按空格键能够顺畅实现图元时序渐显，按 `N` 键顺利唤出认知抽屉，移动端与 PC 端自适应响应。
