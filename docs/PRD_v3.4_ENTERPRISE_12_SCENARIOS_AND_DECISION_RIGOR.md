## 2. 背景与核心问题剖析 (Background & Problem Statement)

动效与视觉表现力解决的是演示文稿的“吸引力与高级感”，但在严肃的企业级组织协同环境中，一份 PPT 的最终成败取决于其**内容逻辑的严密自洽性**、**问题剖析的深刻性**以及**能否有效推动业务决策**。

调研发现，企业内部汇报普遍存在以下四大严重共性硬伤：

```
┌────────────────────────────────────────────────────────┐     ┌────────────────────────────────────────────────────────┐
│             硬伤一：终局缺位，无法促成管理决策         │     │            硬伤二：外部对标片面浮夸，丧失公信力        │
├────────────────────────────────────────────────────────┤     ├────────────────────────────────────────────────────────┤
│ • 汇报耗费大量篇幅陈述业务复杂性，最后以“谢谢大家”或   │     │ • 对标外部友商或竞品时，采用“我方全打绿勾、友商全打红 │
│   “后续持续推进”空洞收尾；                             │     │   叉”的虚假狂妄对比；                                 │
│ • 领导听完一脸迷茫：“所以你今天来找我是要钱、要人、   │     │ • 忽视迁移成本、沉没成本与适用边界，在管理层与评审委   │
│   还是要拍板方案？”错失最佳决策窗口。                   │     │   员会提问面前迅速被攻破。                             │
└────────────────────────────────────────────────────────┘     └────────────────────────────────────────────────────────┘
┌────────────────────────────────────────────────────────┐     ┌────────────────────────────────────────────────────────┐
│             硬伤三：述职沦为流水账，无法证明净增量     │     │            硬伤四：场景认知错配，套用千篇一律模板      │
├────────────────────────────────────────────────────────┤     ├────────────────────────────────────────────────────────┤
│ • 晋升或日常汇报把“一年的工作日程”平铺直叙，堆砌琐碎   │     │ • 故障复盘写成表彰总结；立项答辩写成产品说明书；       │
│   任务（参与了A、协助了B、跟进了C）；                  │     │ • 跨部门拉通缺乏对接口径与依赖甘特图；人头评审缺乏 ROI │
│ • 混淆大盘自然红利与个人真实净贡献，缺乏方法论沉淀。   │     │   测算；未针对特定受众的心理防线设计攻防逻辑。         │
└────────────────────────────────────────────────────────┘     └────────────────────────────────────────────────────────┘
```

为了彻底终结上述企业汇报通病，`undoPPT v3.4.0` 提出以**“决策闭环（Decision-Ready Ask）”**、**“外部立体对标（Rigor in Benchmarking）”**与**“12 大核心场景专业推演”**为支柱的升级方案。

## 4. 向上汇报两大核心规约 (Executive Briefing Rigor)

### 4.1 终局“请领导决策事项”规约 (EPIC-DECISION-ASK)

任何面向管理层、评审委员会或决策者的报告，其最终交付价值不是汇报信息本身，而是**促成高质量、低摩擦的管理决策**。

#### 4.1.1 图元契约扩展 (`summary` 图元增强)

#### 4.1.2 渲染实现规范
* **PPTX 矢量端**：
  - 自动将 `options` 渲染为 2~3 列横向对比卡片；
  - 对 `recommended: true` 的方案卡片施加 Primary 品牌色高亮描边与“★ 推荐方案 / RECOMMENDED”角标；
  - 底部渲染 Recommendation 呼应横幅，以及带有方框 Checkbox 的 `sign_off_items` 审批事项清单。
* **HTML 端**：
  - 渲染高保真玻璃拟态决策中枢卡片；
  - `sign_off_items` 渲染为**真实可交互勾选的 Checkbox 控件**，管理者在投屏或演播演示时可直接当场勾选决议项，形成现场决策的强烈仪式感与闭环。

### 4.2 外部对标充分性规约 (EPIC-RIGOR-BENCHMARK)

针对涉及外部对标、技术选型或竞品分析的页面（如 `standard_table`, `matrix_2x2`），制定严格的对标质量审查标准：

1. **三维立体对标参照系 (3-Way Reference Frame)**：
   - 严禁单一竞品孤证对比；
   - 必须涵盖三大参照系：① 行业头部标杆 (Leader Benchmark)；② 直接同态竞品 (Direct Competitor)；③ 维持现状方案 (Do-Nothing / In-house Status Quo)。
2. **客观优劣对等呈现 (Balanced Trade-offs)**：
   - 严禁“我方全优、竞品全劣”的虚假狂妄表格；
   - 必须客观指出我方的短板与妥协（例如：“迁移学习成本较高”、“成熟案例仍在培育期”等）；
   - 对标维度必须覆盖：成本 (TCO)、交付周期、迁移摩擦、团队认知门槛与技术演进弹性。
3. **适用边界声明 (Boundary of Applicability)**：
   - 明确指出不同方案的最佳适用场景与禁忌场景。

## 5. 晋升述职与常规工作战功归因规约 (EPIC-PROMOTION-ATTRIBUTION)

在晋升述职 (`promotion_assessment`) 与年度成果复盘中，AI Agent 与认知策划引擎必须遵循以下战功萃取铁律：

1. **去噪与净增量归因 (Net Incremental Contribution)**：
   - 严禁将业务自然大盘红利包装为个人核心贡献（例如：“所在部门流水增长 50%”，必须追问“其中由你主导的策略带来的净增量是多少”）；
   - 必须使用严密的 **STAR 结构**：Situation (面临的核心困境与阻力) → Task (承担的角色边界) → Action (具体采取的独创动作与关键解法) → Result (剥离大盘后的量化净收益)。
2. **思考厚度与认知溢出 (Methodological Depth & Organizational Lift)**：
   - 区分“优秀执行者”与“骨干/专家”的关键在于是否具备思考厚度；
   - 成果不仅是做完了业务项目，更要展现将单次解法沉淀为可复用的组件库、SOP 或技术标准，实现组织级的认知赋能。
3. **下一职级承诺与前瞻格局 (Forward-Looking Horizon)**：
   - 述职收尾必须包含对下一职级的清晰定位与规划承诺，展现超越当前岗位局限的业务格局与担当。

## 6. 自动化审计规则扩展 (Automated Audit Rules)

`core/content_auditor.py` 新增以下企业级专项审计规则：

| 规则代码 | 严重等级 | 触发条件 | 扣分标准 | 修复引导建议 |
| :--- | :--- | :--- | :--- | :--- |
| `DECISION_ASK_MISSING` | `warning` | 管理类汇报 (`strategic_planning`, `project_charter`, `annual_strategy_okr`, `team_headcount_review`, `tech_rfc_review`) 收尾页未提供明确的待决策决议项或审批清单 | 扣 4 分 | 在收尾页增加 `sign_off_items` 或 `options` 对比，明确请求领导批复的事项。 |

## 7. 质量验收标准 (Acceptance Criteria)
